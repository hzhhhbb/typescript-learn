Node.js 运行时

npm、vite、你的 Todo API——全都跑在 Node 上。这课建立运行时层的心智模型：Node 是什么、怎么跑你的 TS、和浏览器有什么区别、事件循环怎么工作。第一课的回声：Node 只认识 JS。

⏱ 15-20 分钟

Node.js 是什么

全新概念 Node.js：在浏览器之外执行 JavaScript 的运行时。它给了 JS 两样浏览器没有的东西：文件系统（fs）和完整网络能力（http）——这让 JS 能做后端。
C#（你的已知）Node.js
.NET 运行时 / CLR（执行 IL）Node 运行时（执行 JS）
dotnet run 启动程序node app.js 启动程序
运行时带类型元数据运行时无类型信息（第一课）
关键差异：Node 只执行 JS，不做类型检查。node app.ts 直接跑不了——TS 必须先被 tsc 编译成 JS（第一课的编译管线），node app.js 才认识。这也是你 tsconfig 里 outDir 的由来。

TS → Node 的完整管线

// 你写的 TS
$ cat src/app.ts
let x: number = 42; console.log(x);

// 第一步：编译（tsc 把 TS 变 JS，类型擦除）
$ npx tsc
（生成 dist/app.js，类型消失）

// 第二步：Node 执行 JS
$ node dist/app.js
42
现代开发也有"直接跑 TS"的工具（tsx、ts-node）——它们在内部替你完成了"编译 + 运行"两步。但理解底层管线永远有用：生产部署、调试、排查问题时你看到的还是这两步。

Node vs 浏览器：两个 JS 世界

同一门语言，两套环境。区别在谁提供 API：

能力浏览器Node
全局对象window、document（DOM）process（进程）、global
文件系统✗（浏览器不能读写本地文件）node:fs ✓
网络fetch（Web API）node:http（服务端）+ fetch
共同拥有console、setTimeout、Promise（语言本身）
你已经知道 语言核心（语法、Promise、async/await）两边一样；环境 API 不同。你写前端（React）时用浏览器的 DOM；写后端（Todo API）时用 Node 的内置模块。TS 的类型系统帮你区分：tsconfig 的 lib 里配了 DOM 才有 document 的类型，配了 @types/node 才有 process 的类型。

事件循环：单线程怎么扛住并发

全新概念 Node 是单线程 + 事件驱动 + 非阻塞 I/O：
  • 单线程：一次只执行一段 JS（不像 C# 每请求一线程/线程池）
  • 非阻塞：遇到 I/O（读文件、网络请求）不傻等，而是"记下回调，先去干别的"
  • 事件循环：I/O 完成时，事件循环把对应回调捡回来执行
// 理解非阻塞：这段代码的输出顺序会颠覆 C# 直觉
console.log("1. 开始");

setTimeout(() => console.log("3. 定时器回调"), 0);

console.log("2. 结束");
// 输出：1. 开始 → 2. 结束 → 3. 定时器回调

为什么 0 毫秒的定时器也在最后？因为 setTimeout 是 I/O 类操作——它把回调交给事件循环，主线程先跑完同步代码，事件循环再回来执行回调。这就是第八课 await 能"暂停当前函数但不卡死程序"的底层机制。

C#（你的已知）Node
线程池 + 每请求分配线程单线程事件循环，所有请求共享
async/await 由线程切换实现async/await 由事件循环实现（无线程切换）
CPU 密集任务要线程池CPU 密集任务会阻塞事件循环（worker_threads 补救）
这是 Node 唯一的"性能红线"：别在事件循环里做耗时同步操作（大循环、同步读大文件）。它一阻塞，整个服务器的所有请求都卡住。C# 里一个线程阻塞只影响那个请求。

内置模块：后端工具箱

所有内置模块用 node: 前缀导入（第九课的模块语法）：

模块干什么示例
node:fs文件系统读写readFileSync、writeFile
node:path跨平台路径处理join、basename、extname
node:httpHTTP 服务器/客户端createServer（第十课用过）
process（全局）进程信息env、argv、cwd()、exit()
// node-runtime.ts 实测：文件 + 路径 + 进程
import { readFileSync, writeFileSync } from "node:fs";
import { join } from "node:path";

const filePath = join(process.cwd(), "data.txt");  // 跨平台路径
writeFileSync(filePath, "Hello from Node!");
console.log(readFileSync(filePath, "utf-8"));       // Hello from Node!

console.log(process.env.NODE_ENV ?? "未设置");          // 环境变量（第四课 ??）
console.log(process.argv.slice(2));                   // 命令行参数（去掉 node 和文件名）

动手练习

在 code/ 里验证（5 分钟）

示例在 code/src/node-runtime.ts（已验证）。做几件事：

  1. 运行 npx tsc && node dist/node-runtime.js hello world——看到 ['hello', 'world']（命令行参数进到了 process.argv）。
  2. 挑战 1：node -e "console.log(1+1)" ——不用建文件，直接执行一行 JS。再试试 node -e "console.log(typeof process)"。
  3. 挑战 2（推荐）：把 data.txt 的读写改成异步版 readFile/writeFile（回调版或 fs/promises 的 await 版）——用上第八课的 async/await，体验"非阻塞"。
  4. 挑战 3：给 Todo API 加一个 GET /health 端点，返回 { status: "ok", uptime: process.uptime() }——用 process 暴露运行时信息。

检查你的理解

Q1 · Node 定位

  • JS 的运行时
  • JS 的编译器
  • 包管理器
  • 前端框架
Node 在浏览器外执行 JS（≈ .NET 运行时之于 IL）。编译是 tsc 的事，装包是 npm 的事，界面是框架的事——Node 只管"跑 JS"。

Q2 · TS 执行管线

  • 报错，Node 只认 JS
  • 正常运行，自动编译
  • 报错，缺少 tsconfig
  • 正常运行，忽略类型
Node 只执行 JS，不认识 TS。必须先 tsc 编译成 .js 再 node 执行（tsx/ts-node 是内部替你做了这两步）。

Q3 · Node vs 浏览器

  • node:fs
  • document
  • window
  • alert
fs（文件系统）是 Node 独有——浏览器出于安全不能读写本地文件。document/window/alert 是浏览器独有。console/Promise/fetch 两边都有。

Q4 · 事件循环

  • 单线程事件驱动
  • 每请求分配线程
  • 多线程加锁同步
  • 协程抢占调度
Node 单线程 + 事件驱动 + 非阻塞 I/O：I/O 完成时事件循环捡回回调执行。与 C# 的线程池模型相反。CPU 密集的同步操作会阻塞整个事件循环——性能红线。
