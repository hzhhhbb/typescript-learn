Lesson 0012 · 生态 · 工具层

npm 与 npx：装包与跑命令

TS 生态的第一层：npm 管理依赖（≈ NuGet + dotnet restore），npx 运行包内命令（≈ dotnet tool）。你在前 11 课已经用过它们无数次，这课把心智模型补齐——你天天敲的 npm install 到底在做什么。

⏱ 15-20 分钟

npm 是什么

全新概念 npm（Node Package Manager）：Node 的包管理器。它是三层东西合体——比 NuGet 职责更宽：
  • 包仓库：全球最大的代码仓库（200 万+ 包），typescript、react、vite 全在这（≈ nuget.org）
  • 安装器：下载依赖到本地 node_modules（≈ dotnet restore 到 ~/.nuget/packages）
  • 命令运行器：执行 package.json 里的 scripts（≈ dotnet build 这类项目级命令）
TS 生态C# 生态（你的已知）
npm install <pkg>dotnet add package
npm install（恢复全部）dotnet restore
package.json.csproj（项目清单）
package-lock.jsonpackages.lock.json（版本锁定）
node_modules/全局 NuGet 包缓存（但 npm 是项目本地的）
npm run <script>项目级自定义命令
你已经知道 概念和 NuGet 一样：声明依赖 → 还原 → 使用。关键差异：NuGet 的包是全局缓存 + 引用；npm 的依赖下载到每个项目自己的 node_modules（同一个包每个项目各有一份）。好处是版本隔离（两个项目可以用不同版本的 react），代价是磁盘占用。

package.json：项目清单

打开你的 code/package.json，逐块拆解：

{                                       // 顶层
  "name": "code",                // 项目名（npm 包名规范：小写+连字符）
  "version": "1.0.0",           // 项目版本（语义化版本）
  "scripts": {                    // 自定义命令（第九课）
    "build": "tsc",
    "start": "node dist/main.js",
    "dev": "tsc --watch"
  },
  "type": "commonjs",          // 模块格式（第九课 CJS/ESM）
  "devDependencies": {            // 开发依赖（见下节）
    "typescript": "^7.0.2",
    "@types/node": "^26.2.0"
  }
}

dependencies vs devDependencies

两类依赖，语义完全不同：

dependenciesdevDependencies
装法npm install <pkg>npm install -D <pkg>
用途运行时需要（express、react）开发/构建时需要（typescript、vite、测试工具）
部署时生产环境也要装生产环境可不装
直觉判断法：编译产物里 require/import 到的包 → dependencies；只在构建命令里出现的包 → devDependencies。typescript 属于后者——编译完就完成了使命，运行时不需要它（第一课：编译后是 JS）。react、express 属于前者——产物要跑起来需要它们。

语义化版本：^7.0.2 是什么意思

版本号三段：主版本.次版本.补丁（7.0.2）。前缀符号决定"装依赖时允许更新到什么程度"：

写法含义例子
^7.0.2允许次版本和补丁更新，不允许主版本变（最常用）可升到 7.x.x，不升 8.x.x
~7.0.2只允许补丁更新可升到 7.0.x
7.0.2（精确）锁定，不许动永远是 7.0.2
你已经知道 C# 里对应 NuGet 的版本范围（[7.0, 8.0) 区间）。^7.0.2 ≈ [7.0.2, 8.0.0)。package-lock.json 把最终解析的精确版本记录下来，保证"你的机器和别人机器装的一样"（≈ packages.lock.json 的锁定作用）。

npx：不安装，直接跑

全新概念 npx（npm 5.2+ 自带）：临时运行包内的命令行工具，不需要全局安装。你每天都在用它——npx tsc 就是"运行项目 node_modules 里的 tsc，不全局装"。 
$ npx tsc --version
Version 7.0.2            # 用的是项目本地装的 typescript

$ npx create-vite@latest   # 临时下载并运行脚手架（0014 课的主角）
命令在做什么C# 对照
npm run build执行 package.json scripts 里定义的 build项目自定义 target
npx tsc运行 node_modules 里 tsc 包的命令dotnet tool run（近似）
区分：npm run 跑你自己 scripts 里定义的命令；npx 跑某个包提供的命令。没有 npm run 和 npx 的区别，你就要把 tsc 全局安装——而全局安装的版本会污染所有项目（项目 A 要 tsc 5、项目 B 要 tsc 7，全局只有一个）。

动手练习

在 code/ 里验证（5 分钟）
  1. 运行 npm ls --depth=0——看到你的顶层依赖树（typescript、@types/node）。
  2. 运行 npx tsc --version——确认它输出 Version 7.0.2（用 npx 跑本地包）。
  3. 挑战 1：npm view typescript versions——看 typescript 的全部历史版本（体验"查包不装包"）。再 npm outdated——看有没有可更新。
  4. 挑战 2：装一个包再卸载，走完整流程：npm install -D lodash → 看 package.json 里多了什么 → npm uninstall lodash → 确认它消失。体会 npm 对项目清单的管理。

检查你的理解

Q1 · 开发依赖

  • 装入 devDependencies
  • 装入 dependencies
  • 安装到全局环境
  • 只下载不写入清单
-D = --save-dev，写入 devDependencies（开发/构建时用的包，typescript/vite 都在这里）。运行时需要的包（express/react）用普通 npm install 写入 dependencies。

Q2 · 语义化版本

  • 允许更新到 7.x.x
  • 锁定精确版本 7.0.2
  • 允许任意版本更新
  • 只允许补丁更新
^ 允许次版本和补丁更新（7.x.x），主版本不变。~ 只允许补丁（7.0.x）。无前缀是精确锁定。package-lock.json 记录最终解析的精确版本。

Q3 · npx

  • 显示 tsc 的版本号
  • 显示 npm 的版本号
  • 显示 node 的版本号
  • 报错 tsc 未找到
--version 让 tsc 打印自己的版本：Version 7.0.2。这个 tsc 来自项目本地的 node_modules（npx 的机制）——不是全局安装的，不会污染其他项目。

Q4 · npm run

  • scripts 里的 build 命令
  • npm 内置的构建功能
  • 自动编译所有 TS 文件
  • 安装构建所需依赖
npm run 执行 package.json 里 scripts 定义的命令（你的 build 是 "tsc"）。npm 本身没有内置构建——一切由你定义的 script 决定。
