类型安全实战项目：从零搭一个 Todo API

这课把前面 9 课的全部知识串起来：从空目录开始，搭一个零依赖的 Todo API 服务并跑起来。做完它，你就达到了使命的第二个里程碑——自己从零搭项目。

⏱ 20-25 分钟

项目目标与结构

做一个 HTTP API：创建待办、列出待办、切换完成状态。零第三方依赖（只用 Node 内置 http 模块），三个文件：

todo-api/
├── package.json        # scripts: build / start（第九课）
├── tsconfig.json       # strict + ES2022 + commonjs（第九课）
└── src/
    ├── types.ts        # 类型先行：领域模型（第二/三课）

    └── server.ts       # HTTP 层：路由/异步/校验
我已经把项目完整搭好并全部测试通过，就在 code/todo-api/。课程最后会给你从零重建的完整命令序列（挑战 4）。

第 1 步：类型先行（types.ts）

先定义数据形状，再写任何逻辑——这是类型安全项目的设计哲学：

// types.ts —— 类型先行：先定义数据形状，再写逻辑
export interface Todo {       // 领域模型（第二课 interface）
  id: number;
  title: string;
  done: boolean;
}

// 创建待办的输入：没有 id 和 done——服务器负责生成
export interface CreateTodoInput {
  title: string;
}
设计哲学 类型先行（type-first）：输入类型（CreateTodoInput）和领域模型（Todo）分开——创建时客户端不需要提供 id/done。类型系统让你在编译期就区分"客户端能给的"和"服务器生成的"，写 store 时编译器会强制你补上 id 和 done。

第 2 步：数据层（store.ts）

// store.ts —— 内存存储 + CRUD
import type { Todo, CreateTodoInput } from "./types";  // 第九课 import type

const todos: Todo[] = [];
let nextId = 1;

export function listTodos(): Todo[] { return todos; }

export function createTodo(input: CreateTodoInput): Todo {
  // 类型系统强制：Todo 需要 id、title、done 三个字段
  const todo: Todo = { id: nextId++, title: input.title, done: false };
  todos.push(todo);
  return todo;
}

// 空值：找不到返回 undefined（第四课）
export function toggleTodo(id: number): Todo | undefined {
  const todo = todos.find((t) => t.id === id);
  if (todo) { todo.done = !todo.done; }  // 收窄（第三课）
  return todo;
}

第 3 步：HTTP 层（server.ts）

核心是两个概念：事件驱动的异步（第八课）和 类型管不到网络输入（必须运行时校验）：

// server.ts —— 入口（节选）
import { createServer } from "node:http";
import type { ServerResponse } from "node:http";
import { listTodos, createTodo, toggleTodo } from "./store";

const server = createServer((req, res) => {
  // 路由：方法 + 路径
  if (req.method === "GET" && req.url === "/todos") {
    sendJson(res, 200, listTodos());
    return;
  }

  if (req.method === "POST" && req.url === "/todos") {
    // 读取请求体：事件驱动（第八课）
    let raw = "";
    req.on("data", (chunk) => (raw += chunk));
    req.on("end", () => {
      const input = JSON.parse(raw) as { title?: unknown };
      if (typeof input.title !== "string" || input.title.trim() === "") {
        sendJson(res, 400, { error: "title must be a non-empty string" });
        return;
      }
      sendJson(res, 201, createTodo({ title: input.title.trim() }));
    });
    return;
  }

  // 路径参数：正则解析 + 空值收窄 → 404
  const match = /^\/todos\/(\d+)$/.exec(req.url ?? "");
  if (req.method === "PATCH" && match) {
    const todo = toggleTodo(Number(match[1]));
    if (!todo) { sendJson(res, 404, { error: "todo not found" }); return; }
    sendJson(res, 200, todo);
    return;
  }
  sendJson(res, 404, { error: "not found" });
});
全栈最重要的认知：类型系统管不到网络输入。JSON.parse 返回 any，客户端可能发来任何东西（空字符串、数字、缺字段）。所以 API 边界必须做运行时校验——这是编译期类型检查补不上的最后一道防线。C# 里同样如此（反序列化后要 ModelState 校验）。

动手练习

扩展项目（10 分钟，核心是挑战 1）
  1. 挑战 1（必做）：加一个 DELETE /todos/:id 端点。提示：store.ts 加 deleteTodo(id: number): Todo | undefined（用 findIndex + splice），server.ts 加路由分支（复用 PATCH 的正则匹配），删除成功返回 200 + 被删对象，不存在返回 404。
  2. 挑战 2（推荐）：加 GET /todos?done=true 过滤。提示：用 req.url?.split("?")[1] 取查询串，new URLSearchParams(...) 解析，然后 todos.filter(t => t.done === flag)。
  3. 挑战 3：给 Todo 加 priority: "low" | "medium" | "high" 字段（第三课字面量联合）——类型系统会强制你改 createTodo 和 POST 校验。
  4. 挑战 4（可选）：删掉 todo-api/ 目录（保留 src 之外的全部），按本课命令从零重建一遍——这是"自己从零搭项目"的最终检验。

检查你的理解

Q1 · 运行时校验

  • 网络输入不受类型系统保护
  • 类型系统不检查 string
  • JSON.parse 总是返回正确类型
  • 只有 class 需要校验
JSON.parse 返回 any，客户端可能发任何东西（空串、数字、缺字段）。编译期类型检查到不了 API 边界——运行时校验是最后防线（C# 里对应 ModelState 校验）。

Q2 · 空值收窄

  • if (!todo) 收窄后返回 404
  • 直接把 undefined 发给客户端
  • 强制断言 todo 一定存在
  • 让客户端自己处理空值
存储层返回 Todo | undefined（第三/四课），HTTP 层收窄：不存在 → 404 响应。undefined 不会泄露给客户端。

Q3 · 类型先行

  • 编译器帮你检查所有使用点
  • 因为 C# 里必须分开写
  • 为了加快编译速度
  • 让源码文件更短
类型先行 = 先定义形状再写逻辑：写 createTodo 时编译器强制你补 id/done；改字段时编译器找出所有相关代码（第十课的"改一处找齐所有"）。

Q4 · 事件驱动

  • 事件驱动的异步
  • 同步阻塞读取
  • Promise 自动解析
  • 回调返回 JSON
Node 的流是事件驱动的（第八课）：请求体分块到达触发 data，结束触发 end。代码在 end 里处理完整请求体。这是 Node 异步心智模型的实际应用。
