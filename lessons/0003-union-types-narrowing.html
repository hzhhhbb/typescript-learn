联合类型与类型收窄

"这个值可能是 string，也可能是 number"——在 C# 里你要么用 object 加一堆模式匹配，要么引第三方库。在 TypeScript 里只是一行 type Id = string | number。这课讲联合类型，以及编译器怎么在运行时检查中一步步收窄类型。

⏱ 15-20 分钟

热身：补上第二课没做的挑战（1 分钟）

打开 code/src/structural.ts，取消 pet3 那行的注释，运行 npx tsc，亲眼看到 TS2353，再注释回去。这个亲手体验会强化"字面量 vs 变量"的记忆——比看十遍都管用。

为什么需要联合类型？看看 C# 有多笨重

C# · 你的已知
object id = GetId();
if (id is string name) {
  SearchByName(name);
}
else if (id is int num) {
  SearchById(num);
}
TypeScript · 新的
type Id = string | number;

function lookup(id: Id) {
  if (typeof id === "string") {
    SearchByName(id);  // 已收窄为 string
  } else {
    SearchById(id);    // 已收窄为 number
  }
}
全新概念 联合类型（union type）：A | B 表示"这个值要么是 A 要么是 B"。它是编译期概念——运行时没有任何"联合类型"的对象，只有一个真实的值。
一个常见误解要立刻纠正：联合类型是"或"，但类型合并是"与"。如果两个 interface 合并成一个类型，成员会叠加（交集语义）；而联合是选其一（并集语义）。别搞混。

字面量联合：枚举的轻量替代

把具体值当作类型，组合成"选项集合"——这是 TS 生态里枚举的主流替代品：

type Status = "pending" | "active" | "done";

let s: Status = "pending";  // ✓
s = "done";                    // ✓
s = "cancelled";              // ✗ TS2322
$ npx tsc
src/unions.ts:9:5 - error TS2322: Type '"cancelled"' is not assignable to type 'Status'.
你已经知道 字面量联合 ≈ C# 的 enum，但有区别：TS 也有 enum 关键字，社区却更常推荐字面量联合——因为它只是类型，不产生运行时对象，类型检查更严格（"done" 直接可赋，不用 Status.Done 转换）。全栈代码里你会大量见到这种写法。

类型收窄：编译器跟着你的检查走

联合类型的值在使用前必须先"收窄"到具体类型。收窄的机制是：你在运行时做的检查（typeof、in、instanceof、===），编译器会同步更新编译期的类型。

function lookup(id: Id): string {
  if (typeof id === "string") {
    return id.toUpperCase();  // ✓ 这里 id 是 string，有 toUpperCase
  }
  return `id: ${id}`;         // ✓ 这里 id 是 number
}

// 在检查之外访问联合类型的专属方法 —— 编译错误：
// error TS2339: Property 'toUpperCase' does not exist on type 'string | number'
收窄是"编译期检查跟着运行时检查走"——这正是第一课心智模型的延伸：TS 在编译期模拟你的代码在运行时做什么。检查了 typeof，编译器就信你，把类型范围缩小。

一个经典的坑：typeof null

console.log(typeof null);  // "object" —— 不是 "null"！

这是 JavaScript 的历史遗留 bug（1995 年就存在）。后果：typeof x === "object" 检查不会排除 null。判断"可能是 null 的对象"要用 x !== null 或 x == null 或 x === null，而不是 typeof。

可辨识联合：switch 收窄的完整形态

这是全栈开发里最高频的联合类型模式——用一个 kind 字段区分每种分支：

type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "square"; size: number };

function area(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2;  // shape 收窄为 circle 分支
    case "square":
      return shape.size * shape.size;        // shape 收窄为 square 分支
  }
}
全新概念 可辨识联合（discriminated union）：联合的每个分支都有一个独一无二的字面量标记（kind）。switch 按标记分流，每个 case 里类型自动收窄。

杀手锏：穷尽性检查

给 Shape 加第三种分支，但忘了在 switch 里处理它——编译器会帮你抓到：

type Shape = ... | { kind: "triangle"; base: number; height: number };

// switch 里没有 case "triangle" —— 编译错误：
// error TS2366: Function lacks ending return statement and return type
// does not include 'undefined'.

加新分支时，编译器强制你处理它。这就是"修改一处、编译器帮你找齐所有相关代码"——C# 的 switch 表达式也有穷尽性检查（_ 兜底分支），概念完全一样。

C#（你的已知）TypeScript（新的）
shape switch { Circle c => ..., Square s => ... } 运行时模式匹配switch (shape.kind) { ... } 编译期类型收窄
模式匹配是运行时机制（检查真实对象）收窄是编译期机制（基于你的检查更新类型）

检查你的理解

Q1 · 收窄机制

  • 收窄为 string 类型
  • 仍是 string | number
  • 收窄为 number 类型
  • 变为 any 类型
运行时检查 typeof 后，编译器同步收窄编译期类型。typeof x === "string" 为真的分支里，x 就是 string——可以安全调用字符串专属方法。

Q2 · 字面量联合

  • 编译通过，done 是合法值
  • 编译失败，必须用枚举类型
  • 编译失败，字符串不能做类型
  • 编译通过，s 变为普通字符串
字面量联合把具体值当类型。"done" 在联合里，赋值合法；"cancelled" 不在联合里，报 TS2322。它只是类型，不产生运行时对象（区别于 C# 的 enum）。

Q3 · 可辨识联合

  • 收窄为 circle 分支类型
  • 仍是完整联合类型
  • 收窄为 square 分支类型
  • 变为 any 类型
switch 按 kind 标记分流后，每个 case 里 shape 收窄为该分支类型。若新增分支而忘了加 case，编译器报 TS2366（穷尽性检查）。

Q4 · null 的坑

  • "object"
  • "null"
  • "undefined"
  • "number"
JS 的历史 bug：typeof null === "object"。所以判断"可能是 null 的对象"时，不能用 typeof 排除 null——要显式检查 x !== null。
