⏱ 15-20 分钟

React 是什么：UI = f(state)

全新概念 React：声明式 UI 库。核心心智模型一句话——界面是状态的函数：UI = f(state)。你描述"状态长什么样 → 界面应该是什么样"，React 负责把界面渲染出来，状态变了它自动重新渲染。
C#（你的已知）React
Blazor / Razor 组件React 组件（函数组件是主流）
[Parameter] 传参props（组件的输入）
组件字段 + 事件回调useState + 事件处理器
OnInitializedAsync 拉数据useEffect 副作用
你已经知道 React 不是框架（框架管路由/状态管理/依赖注入），是库——只解决"界面怎么声明"。其余（构建、请求、测试）靠生态里的其他工具——这正是你这四课学到的生态全景。

组件 + JSX：在 JS 里写 HTML

// App.tsx —— 一个组件就是一个函数，返回 JSX
function App() {
  return (
    <div className="app">          // JSX：看起来像 HTML，其实是 JS 表达式
      <h1>Todo 清单</h1>
      <button>添加</button>
    </div>
  );
}
全新概念 JSX：在 JS 文件里写 HTML 标记的语法（.tsx 后缀 = 含 JSX 的 TS）。{大括号} 里可以嵌入任何 JS 表达式。C# 对照：Razor 是"HTML 里混 C#"（@ 语法）；JSX 反过来——JS 里混 HTML。

useState：组件内部状态

const [todos, setTodos] = useState<Todo[]>([]);  // 状态：待办列表
const [title, setTitle] = useState("");       // 状态：输入框文字

// 读取：todos（值）   更新：setTodos(新值)
// 状态变了 → React 自动重新渲染组件（函数重新执行）
全新概念 useState：组件自己的可变状态。返回 [值, 更新函数] 两个东西。关键机制：调用更新函数 → React 重新执行组件函数 → 界面跟着变。你不直接改 todos（用 [...todos, todo] 造新数组）——这是 React 的不变性规则（类似 C# 的 immutable 风格）。

useEffect：副作用（拉数据）

useEffect(() => {
  fetch("http://localhost:3000/todos")   // 第八课的 fetch
    .then((res) => res.json())
    .then((data) => setTodos(data));
}, []);  // 空数组 = 只在组件挂载时执行一次
全新概念 useEffect：在渲染之外做"副作用"（网络请求、订阅、计时器）。第二个参数是依赖数组：[] = 只在挂载时跑一次（≈ Blazor 的 OnInitializedAsync）；不传 = 每次渲染都跑；传变量 = 变量变时才跑。

事件 + 列表渲染

// 事件：onClick / onChange 传处理器函数（第六课函数类型）
<input
  value={title}
  onChange={(e) => setTitle(e.target.value)}   // 打字 → 更新状态 → 重渲染
/>
<button onClick={addTodo}>添加</button>

// 列表渲染：map 生成元素，key 帮 React 区分每一项
{todos.map((t) => (
  <li key={t.id}>{t.done ? "✅" : "⬜"} {t.title}</li>
))}

全栈闭环：这课你亲眼看到的事

你在浏览器打开 localhost:5173（React dev server）
  → App 组件挂载
  → useEffect 里 fetch("http://localhost:3000/todos")
  → 请求到你的 Todo API（第十课写的）
  → API 返回 JSON 列表
  → setTodos(数据) → React 重新渲染 → 页面出现待办列表

你输入文字点"添加"
  → addTodo 里 fetch POST
  → API 创建待办（id 自动生成）
  → setTodos([...todos, todo]) → 列表更新
真实遇到的坑：CORS。React dev server（localhost:5173）请求 API（localhost:3000）——跨域。浏览器安全策略会拦截（"No 'Access-Control-Allow-Origin' header"）。解决办法：API 响应加 Access-Control-Allow-Origin 头（我已加好，见 Todo API 的 server.ts）。全栈开发第一天就会碰到它。

检查你的理解

Q1 · state 机制

  • 组件重新渲染
  • 整个页面刷新
  • 浏览器重新加载
  • 需要手动刷新
更新函数被调用 → React 重新执行组件函数 → 界面自动更新（UI = f(state)）。React 只更新需要变的部分，不是整页刷新。

Q2 · 副作用时机

  • 只在挂载时执行一次
  • 每次渲染都执行
  • 永远不会执行
  • 每秒执行一次
依赖数组为空 = 没有依赖 → 只在组件挂载时跑一次（拉数据的标准写法）。≈ Blazor 的 OnInitializedAsync。

Q3 · key

  • 帮助 React 区分列表项
  • 给元素添加样式
  • 控制列表的排序
  • 绑定点击事件
key 是列表项的唯一标识——React 靠它知道"哪个项更新/删除/新增"（相当于 C# 里对象的 Id）。用数组下标当 key 是反模式（顺序变就错乱）。

Q4 · CORS

  • 跨域安全限制
  • API 地址写错了
  • React 不支持 fetch
  • 后端端口被占用
不同端口 = 不同源。浏览器安全策略拦截跨域请求，除非后端响应带 Access-Control-Allow-Origin 头。全栈开发必踩的坑。
