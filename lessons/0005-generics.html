Lesson 0005 · 类型系统

泛型：熟悉的名字，陌生的底层

你闭着眼睛都会写 C# 的 List<T>。但 TS 的泛型有一个本质差异：它只在编译期存在，运行时完全消失。这课帮你建立正确的 TS 泛型心智模型，语法上你几乎零学习成本。

⏱ 15-20 分钟

语法对照：几乎一样

C# · 你的已知
T Identity<T>(T value) {
  return value;
}

class Box<T> {
  public T Value { get; }
}
TypeScript · 新的
function identity<T>(value: T): T {
  return value;
}

class Box<T> {
  constructor(public value: T) {}
}
C#（你的已知）TypeScript（新的）
Box<int> b = new();const b = new Box<number>(42);

调用时类型参数自动推断，不用手写：

const n = identity(42);    // T 自动推断为 number
const s = identity("hi");  // T 自动推断为 string
你已经知道 类型推断 ≈ C# 泛型方法调用时的推断（Identity(42) 不用写 <int>）。行为一致，无需多学。

最重要的差异：泛型在运行时消失

这是本课的核心，请刻进脑子：

全新概念 TS 泛型的类型擦除：Box<number> 和 Box<string> 编译后是完全相同的代码——就是一个普通对象。对比 C#：List<int> 和 List<string> 是运行时不同的类型（JIT 特化、有泛型元数据）。TS 没有这些，泛型纯粹是编译期文档和检查。 
// 源码
const numBox: Box<number> = { value: 42 };
const strBox: Box<string> = { value: "hi" };

// 编译后（类型擦除）
const numBox = { value: 42 };
const strBox = { value: "hi" };

三个直接后果：

  • 不能 instanceof T：T 在运行时不存在，没法判断。C# 里 typeof(T) 合法，TS 里没有对应物。
  • 类型参数只用于编译期检查：numBox.value + 1 能通过编译是因为类型系统知道 value 是 number；运行时它就是普通属性访问。
  • 运行时"类型区分"要靠值：想区分不同类型，用可辨识联合的 kind 字段（第三课学的），而不是泛型。

泛型约束：extends（≈ where T : ...）

// C#:  T Longest<T>(T a, T b) where T : IComparable
function longest<T extends { length: number }>(a: T, b: T): T {
  return a.length >= b.length ? a : b;
}

console.log(longest("abc", "xy"));        // "abc" —— string 有 length
console.log(longest([1, 2, 3], [4, 5])); // [1,2,3] —— 数组有 length
longest(1, 2);                       // ✗ TS2345: number 没有 length
$ npx tsc
src/_err.ts:4:9 - error TS2345: Argument of type 'number' is not assignable
to parameter of type '{ length: number; }'.
C# 约束TS 等价
where T : IComparable<T extends { compareTo(...): number }>（结构类型：有这形状就行）
where T : class<T extends object>
where T : new()<T extends new (...args: any[]) => any>（构造签名）
where T : notnull默认就是（strict 下 <T> 可包含 null，需要时加 <T> 后用联合约束）
注意 TS 的约束是结构性的（第二课）：T 不需要"实现"某个接口，只要有相应成员即可。所以 "abc" 和 [1,2,3] 都能满足 { length: number }。

泛型 + 收窄：经典组合

class Stack<T> {
  private items: T[] = [];
  push(item: T): void { this.items.push(item); }
  pop(): T | undefined {  // 数组可能为空 → 第四课技能
    return this.items.pop();
  }
}

const stack = new Stack<number>();
const top = stack.pop();  // number | undefined —— 必须先收窄才能用
if (top !== undefined) {
  console.log(top + 1);  // ✓ 收窄为 number
}

预告：infer（C# 完全没有的东西）

TS 泛型的终点是"类型编程"。下一个里程碑是 infer——从类型中提取子类型：

type ElementType<T> = T extends (infer U)[] ? U : never;

type A = ElementType<string[]>;  // string
type B = ElementType<number[]>;  // number

现在不用会写，只需要知道它存在。0012 课（映射类型与条件类型）再展开。

检查你的理解

Q1 · 泛型推断

  • number
  • any
  • Object
  • unknown
调用时从实参推断：identity(42) 的 T = number。和 C# 泛型方法推断一样，不用手写类型参数。

Q2 · 类型擦除

  • 相同代码，无类型区分
  • 两个不同的类
  • 编译报错不能共存
  • 运行时检查值类型
TS 泛型编译后完全擦除，Box<number> 和 Box<string> 是同一段代码。对比 C#：List<int> 与 List<string> 是运行时不同类型。这是两者最本质的差异。

Q3 · 泛型约束

  • where T : 接口类型
  • where T : class
  • where T : struct
  • where T : new()
extends { length: number } ≈ where T : IHasLength——但 TS 是结构约束：不需要实现任何接口，有 length 成员即可（所以 string 和数组都满足）。

Q4 · 约束的意义

  • 限制 T 必须具有 length 成员
  • 让 T 变成 any 类型
  • 给 T 添加运行时信息
  • 加快编译速度
约束让函数体内可以安全使用 a.length，且调用时违反约束的实参会报 TS2345。它只有编译期意义，不产生任何运行时代码。
