函数与对象类型

全栈代码里 80% 的类型知识都在这课：回调怎么写类型、可选/剩余参数、函数重载的 TS 写法、readonly 和索引签名。函数是 JS 世界的头等公民——类型系统对函数的重视程度远超 C#。

⏱ 15-20 分钟

函数类型：≈ C# 的 Func / 委托

TS 里函数本身是一种值，有自己的类型。语法是"参数列表 + 箭头 + 返回类型"：

C#（你的已知）TypeScript（新的）
Func<int, int, int> op = (a, b) => a + b;type MathOp = (a: number, b: number) => number;
Action<int> log = n => Console.WriteLine(n);type Log = (n: number) => void;
type MathOp = (a: number, b: number) => number;

const add: MathOp = (a, b) => a + b;       // 参数类型从 MathOp 推断
const multiply: MathOp = (a, b) => a * b;
console.log(add(2, 3));  // 5
你已经知道 概念和 C# 的委托/Func 一样：函数作为值传递。差异只在语法——TS 把返回类型写在箭头后面，C# 写在 Func<> 尖括号里。

回调参数：全栈代码的常态

数组方法、事件、API 层全是回调。回调参数的类型直接写函数类型：

function forEach(
  arr: number[],
  callback: (item: number, index: number) => void
): void {
  for (let i = 0; i < arr.length; i++) {
    callback(arr[i], i);
  }
}

forEach([10, 20, 30], (n, i) => console.log(`#${i}: ${n}`));
// #0: 10
// #1: 20
// #2: 30
回调签名必须匹配，否则编译报错。比如回调里写了 (item: string) 而数组是 number[]——TS2345。错误信息会精确指出签名差异。这是 TS 保护回调类型安全的主要手段。

可选参数、默认参数、剩余参数

C#TypeScript
void Greet(string n, string g = "Hello")function greet(name: string, greeting = "Hello")
void Log(string msg, bool verbose)（重载处理可选）function log(msg: string, verbose?: boolean)
int Sum(params int[] nums)function sum(...nums: number[])
// 可选参数 ?：不传就是 undefined
function greet(name: string, greeting?: string): string {
  return `${greeting ?? "Hello"}, ${name}!`;  // ?? 兜底（第四课）
}
greet("Ada");       // Hello, Ada!
greet("Ada", "Hi"); // Hi, Ada!

// 默认参数：不传就用默认值（类型推断为 string）
function greet2(name: string, greeting = "Hello"): string {
  return `${greeting}, ${name}!`;
}

// 剩余参数 ...：收集所有实参为数组
function sum(...nums: number[]): number {
  return nums.reduce((acc, n) => acc + n, 0);
}
console.log(sum(1, 2, 3, 4));  // 10
规则：可选参数（?）和剩余参数必须在参数列表末尾——和 C# 一样。

函数重载：TS 的独特写法

C# 重载是写多个同名方法定义。TS 的写法不同：多个签名声明 + 一个兼容所有签名的实现。

// 签名 1：传 string 返回 string
function pick(input: string): string;
// 签名 2：传 number 返回 number
function pick(input: number): number;
// 实现：参数和返回类型必须是所有签名的"并集"
function pick(input: string | number): string | number {
  return typeof input === "string" ? input.toUpperCase() : input * 2;
}

const a = pick("hi");  // 类型：string（按签名 1）
const b = pick(21);   // 类型：number（按签名 2）
全新概念 调用方看到的是签名列表，实现是隐藏的。好处：pick("hi") 的类型是 string、pick(21) 是 number——比返回 string | number 精确得多。C# 里这是重载的自然结果；TS 用签名+实现模拟。

对象类型：readonly 与索引签名

// readonly：属性不可重新赋值（编译期检查）
interface Point {
  readonly x: number;
  y: number;
}
const p: Point = { x: 1, y: 2 };
p.x = 10;  // ✗ TS2540: Cannot assign to 'x' because it is a read-only property
// 索引签名：动态键的对象（字典/映射）
interface StringMap {
  [key: string]: string;  // 任意字符串键 → string 值
}
const dict: StringMap = { hello: "你好", world: "世界" };
console.log(dict.hello);  // 你好
你已经知道 readonly ≈ C# 的 readonly 字段 / get-only 属性。索引签名 ≈ C# 的 Dictionary<string, string> 或索引器——但 TS 是纯类型声明，对象本身是普通 JS 对象。

检查你的理解

Q1 · 函数类型

  • Func<int, string>
  • Action<string>
  • Event 委托类型
  • async 方法签名
函数类型 (a: number) => string = 入参 number、出参 string = Func<int, string>。Action 无返回值（对应 => void）。

Q2 · 可选参数

  • 编译通过，greeting 是 undefined
  • 编译失败，缺少实参
  • 编译通过，greeting 是空串
  • 编译失败，可选不能省略
可选参数不传就是 undefined——类型是 string | undefined。函数体内要用 ?? 或收窄处理（示例里用了 greeting ?? "Hello"）。

Q3 · 剩余参数

  • params int[] nums
  • out int[] nums
  • ref int[] nums
  • IEnumerable<int>
...nums: number[] 收集所有实参为数组 = C# 的 params int[]。注意它和"接收一个数组参数"的区别：调用时直接 sum(1, 2, 3) 而不是 sum([1,2,3])。

Q4 · 重载

  • 多个签名加一个实现
  • 多个同名方法定义
  • 一个签名加多个实现
  • 运行时动态分发
TS 重载 = 多个签名声明（无函数体）+ 一个兼容所有签名的实现。调用方按签名获得精确类型。多个同名方法定义是 C# 的做法，TS 不支持（同一作用域同名函数只有一个）。
