Lesson 0004 · 类型系统

null、undefined 与严格空检查

JavaScript 有两个"空"——这是它和 C# 最烦人的差异之一。"undefined is not a function"是 JS 世界头号报错。这课把这堆问题连根拔掉，好消息是：处理空值的两个主力操作符（?. 和 ??）你已经在 C# 里用熟了。

⏱ 15-20 分钟

先认识两个"空"

C# 里只有一个 null。JavaScript 有两个不同的空值，语义完全不同：

值含义典型产生场景
undefined"这个值根本不存在"访问不存在的对象属性、读取未赋值的变量、函数没有 return、可选属性缺席、可选链落在空处
null"开发者显式表示这里没有值"你主动写 let x = null、API 返回 null
记住这个区分：undefined 是"系统给的没有"，null 是"人给的没有"。C# 里只有 null；TS 里两者并存，而且类型检查对它们一视同仁（都可空、都要收窄）。

严格空检查（strictNullChecks）

你的 tsconfig 里 strict: true 包含 strictNullChecks。开启后，null/undefined 不能赋给普通类型：

const name: string = null;   // ✗ TS2322: Type 'null' is not assignable to type 'string'

const nick: string | null = null; // ✓ 显式声明可空
const maybe: string | undefined = undefined; // ✓
你已经知道 这等价于 C# 8+ 的可空引用类型（<Nullable>enable</Nullable>）。区别在于严格度：C# 里 string? 显式可空，string 不可空；TS 里 string 直接不可空，想要可空必须写 string | null——没有"代码库迁移"的灰色地带。这也是为什么 TS 代码里联合类型满天飞。

处理空值的四个武器

武器 1：可选链 ?. —— 和 C# 一模一样

interface User {
  name: string;
  address?: { city?: string };  // 可选 → 类型是 { city?: string } | undefined
}

const user: User = { name: "Ada" };  // 没有 address

const city = user.address?.city;  // undefined，不抛异常！
// user.address.city               // ✗ 这样写：TypeError: Cannot read properties
//                                 //   of undefined (reading 'city')

链上任何一环是空，整个表达式返回 undefined。支持调用（fn?.()）和索引（arr?.[0]）。你的 C# 经验直接迁移。

武器 2：空值合并 ?? —— 和 C# 一模一样

function getTimeout(cfg: Config): number {
  return cfg.timeoutMs ?? 5000;  // timeoutMs 是 number | undefined → ?? 给默认值
}

武器 3：非空断言 ! —— 逃生舱，慎用

const bad = user.address!.city;  // 编译通过，但运行时 address 是 undefined → 崩溃

! 告诉编译器"这里不会是空，跳过检查"。它和 C# 的 !（null-forgiving operator）一样，是对编译器的承诺——承诺错了，运行时直接崩。只在你有确凿把握时用。

武器 4：收窄（你已会的第三课技能）

if (user.address) {
  console.log(user.address.city);  // 收窄后安全访问
} else {
  console.log("no address");
}
优先级建议：收窄 > ?. > ?? > !。! 应是最少见的写法。

大坑：?? vs ||

新手常把 ?? 当 || 用，但两者对"假值"的态度完全不同：

操作符当左侧为 0 / "" / false 时当左侧为 null / undefined 时
a ?? b返回 a（0、""、false 都是合法值）返回 b
a || b返回 b（把它们当"假"）返回 b
function pickNullish(x: number | undefined, fb: number): number {
  return x ?? fb;  // 0 ?? 100 = 0
}
function pickFalsy(x: number, fb: number): number {
  return x || fb;  // 0 || 100 = 100
}
全栈真实场景：端口号 0、重试次数 0、布尔开关 false 都是合法的业务值。用 || 兜底会把它们悄悄换成默认值——这是非常隐蔽的 bug。?? 只认"真空"。
环境注意 你的环境装的是 TypeScript 7（新原生编译器）。它新增了严格检查：0 ?? 100 这种"左侧静态上永不可能是空的 ??"会直接报错（TS2869），"" || x 这种"永远为假"也会报（TS2873）。老教程里的演示代码在你机器上可能编译不过——看到这两个错误码，说明 TS 在提醒你"这个兜底永远不生效"。

检查你的理解

Q1 · 严格空检查

  • 编译失败，null 不能赋给 string
  • 编译通过，null 是合法空值
  • 编译通过，name 自动变为可空
  • 编译失败，必须标注 any
strictNullChecks 下 string 不含 null。想要可空必须显式写 string | null——和 C# 可空引用类型类似，但没有灰色地带。

Q2 · 可选链

  • 返回 undefined，不抛异常
  • 返回 null，不抛异常
  • 抛 TypeError 异常
  • 返回空字符串
可选链上任何一环为空，整个表达式短路返回 undefined。C# 的 ?. 语义一致。

Q3 · 空值合并

  • 0，0 不是 null/undefined
  • 100，0 被当作假值
  • undefined，x 是 0
  • 100，?? 总返回右侧
?? 只对 null/undefined 生效。0 是合法值，原样返回。这是它与 || 的核心区别（|| 会把 0 当假）。

Q4 · undefined vs null

  • 访问不存在的对象属性
  • 开发者显式赋 null
  • 函数返回 null 字面量
  • 变量初始化为 null
undefined 是"系统给的没有"（访问不存在属性、未赋值变量、无 return 的函数）；null 是"人给的没有"（显式写 null）。两者都要按可空处理。
