Lesson 0001 · 环境与心智模型

让 TypeScript 跑起来

你精通 Java 和 C#，所以这课不讲"什么是变量"。我们做三件事：建立 TS 编译管线的心智模型、在你机器上跑通第一个程序、学会读编译错误。

⏱ 15-20 分钟

先说最重要的事：TS 编译后，类型去哪了？

这是整个课程最重要的一张图，请把它刻在脑子里：

// hello.ts（源码，带类型）
let price: number = 99;

// 经过 tsc 编译 ↓

// hello.js（产物，纯 JavaScript，类型没了）
let price = 99;
全新概念 类型擦除（type erasure）：TypeScript 的类型系统只在编译期存在。编译后类型信息全部消失，产出的是纯 JavaScript。运行时没有"变量是什么类型"这一说——只有真实的值。

最直接的后果：instanceof 只能判断真实对象（instanceof Date），不能判断"是不是这个接口的实现"——因为接口在运行时不存在。这个坑我们后面专门讲。

动手：在你机器上跑通

打开终端，建一个练习目录（任选位置，我用 ~/Projects/typescript-learn/code）：

$ cd ~/Projects/typescript-learn/code
$ npm init -y                    # 生成 package.json（≈ csproj 的极简版）
$ npm install typescript --save-dev # 安装 tsc 到本项目
$ mkdir src                      # 源码目录（产物默认进 dist/）

创建 tsconfig.json（不用 tsc --init，那个生成上百行注释；手写 10 行更清晰）：

// tsconfig.json
{
  "compilerOptions": {
    "strict": true,       // ← 必须为 true，相当于 C# 的 nullable 全面开启
    "target": "ES2022",    // 输出 JS 的语法版本
    "module": "commonjs", // 模块系统（后课细讲）
    "outDir": "./dist",    // 编译产物输出目录
    "rootDir": "./src"    // 源码目录
  },
  "include": ["src"]        // 只编译 src/ 下的 .ts
}
项目结构约定：源码放 src/，产物进 dist/，和 Maven 的 src/main/java 一个道理。
你已经知道 strict: true 约等于 C# 里同时开了 Nullable、关闭了隐式 unchecked —— 别偷懒关掉它。官方和社区都把 strict 视为默认。

创建 src/hello.ts：

// hello.ts
let message: string = "Hello, TypeScript!";
let year = 2025;                  // ← 推断为 number，等价于 var year = 2025

function greet(name: string): string {
  return `Hello, ${name}!`;
}

console.log(greet(message));
console.log("Year:", year);
$ npx tsc              # 编译：检查类型 + 产出 dist/
$ node dist/hello.js    # 运行产物
Hello, TypeScript!
Year: 2025
全新概念 语法对照：TS 的类型标注是后缀式（name: string），C# 是前置式（string name）。参数、变量、返回值都这样。习惯就好，30 秒就适应了。

你已经知道 let ≈ var（可重新赋值），const ≈ readonly（不可重新赋值）。JS 的 const 只保证引用不变，不保证内容不变——和 C# 的 readonly 类似，别和 Java 的 final 语义搞混（Java final 对象内容可变）。

练习：制造一个错误，学会读报错

把 hello.ts 里的一行改成：

let year: number = "2025";   ← 类型错误！

再运行 npx tsc，你会看到：

$ npx tsc
src/hello.ts:3:5 - error TS2322: Type 'string' is not assignable to type 'number'.

3 let year: number = "2025";
      ~~~~

Found 1 error in src/hello.ts:3

读报错的三个信息（这条知识价值极高，学会它你的调试效率直接翻倍）：

  • src/hello.ts:3:5 — 文件:行:列，精确定位。
  • error TS2322 — 错误码。2322 = 赋值类型不匹配。报错码是稳定的，可以搜索。
  • Type 'string' is not assignable to type 'number' — 方向永远是"源类型不能赋给目标类型"，先看方向再看类型。

改回来，确认 npx tsc 无输出（无错误）再继续。

检查你的理解

Q1 · 类型不匹配

  • 编译失败，string 不能赋给 number
  • 编译通过，自动转为 number 类型
  • 编译通过，自动转为 string 类型
  • 编译通过，运行时抛出 TypeError
TS 不做隐式类型转换："99" 是 string，不能赋给标注为 number 的变量，编译期直接报 TS2322。这和你熟悉的 C# 一致——int price = "99"; 同样是编译错误。注意：JS 本身会转换，TS 的职责就是拦下这类隐患。

Q2 · 类型擦除

  • let price = 99;
  • let price: number = 99;
  • let price: any = 99;
  • let price = "99";
编译产物里类型标注全部消失：let price = 99;。这就是类型擦除——是"删除"，不是"转换为字符串"，也不是"放宽为 any"。运行时没有任何类型信息。

Q3 · 类型推断

  • 编译失败，x 已被推断为 string 类型
  • 编译通过，x 的类型自动变为 number
  • 编译通过，x 自动放宽为 any 类型
  • 编译通过，运行时抛出 TypeError
推断出来的类型和显式标注同等严格：x 被推断为 string 后，赋 number 会报编译错误。等价于 C# 的 var x = "hello"; x = 42;——同样是编译失败。推断不是"宽松化"，它只是帮你少打字。
独立练习（2 分钟）

不改 tsconfig，想一下再回答：把 "strict" 改成 false 后重新编译 let year: number = "2025";，还会报错吗？先在心里给出答案，再动手验证。（提示：strict 主要管 null 检查和隐式 any，类型不匹配检查不属于它）

看答案

会。2322 错误不受 strict 控制——类型不匹配是 TS 的基础检查。strict 影响的是另一批检查（nullable、implicit any）。这个区分后面会有专课。
