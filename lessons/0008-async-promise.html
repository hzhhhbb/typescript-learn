异步与 Promise

好消息：async/await 和 C# 几乎一模一样。坏消息：fetch 的错误行为和你习惯的 HttpClient 不一样，这里藏着全栈开发最经典的坑。学完这课，你就达到了使命的第一个里程碑——读懂真实全栈代码。

⏱ 15-20 分钟

心智模型：JS 的异步世界观

JS 是单线程的，但它不会阻塞等 I/O——而是把 I/O 交给系统，干完再回来通知你。这个"干完通知你"的机制就是事件循环。你的代码分两种：

  • 同步代码：从上到下立即执行（就像 C# 的普通方法）
  • 异步代码：发起后马上返回一个"占位符"，结果到了再兑现
全新概念 Promise<T>（≈ C# 的 Task<T>）：异步操作的容器，表示"未来会得到一个 T"。状态机：pending（进行中）→ fulfilled（成功，有值）或 rejected（失败，有原因）。await 就是"等它兑现"。

Promise 基础（≈ Task<T>）

// Promise<void>：未来完成、不返回值（≈ Task）
function delay(ms: number): Promise<void> {
  // resolve 被调用 → Promise 完成
  return new Promise((resolve) => setTimeout(resolve, ms));
}

// Promise<T>：未来得到一个值（≈ Task<T>）
async function fetchUser(id: number): Promise<{ id: number; name: string }> {
  await delay(100);  // 模拟网络延迟
  return { id, name: `User ${id}` };
}

const user = await fetchUser(1);  // await 取出值，类型自动推断
console.log(user.name);  // User 1
你已经知道 async/await 与 C# 几乎一致：async function ≈ async Task<T> F()，await ≈ await，调用方拿到的都是"未来的值"类型。你在 C# 里 async/await 的所有直觉，在这里都成立。
关键类型规则：async 函数永远返回 Promise。async function f(): Promise<number> 里写 return 42，但调用 f() 得到的类型是 Promise<number>（不是 number）——必须 await 才能拿到 42。这和 C# 的 async Task<int> 一样。

并行：Promise.all（≈ Task.WhenAll）

async function parallel() {
  // 两个请求同时发出，一起等（不是串行！）
  const [a, b] = await Promise.all([fetchUser(1), fetchUser(2)]);
  console.log(a.name, b.name);  // User 1 User 2
}
新手常见错误：await fetchUser(1); await fetchUser(2); ——这是串行（等完第一个再发第二个）。要并行必须先把 Promise 创建出来再 Promise.all。C# 里对应 Task.WhenAll，规则相同。

真实场景：fetch + 最经典的坑

C# · HttpClient（你的已知）
var res = await client.GetAsync(url);
// 4xx/5xx 默认会抛异常！
res.EnsureSuccessStatusCode();
TypeScript · fetch（新的）
const res = await fetch(url);
// 4xx/5xx 不抛异常！！
if (!res.ok) { throw new Error(`HTTP ${res.status}`); }
全新概念 fetch 的错误模型和 HttpClient 相反：fetch 只在网络故障（断网、DNS 失败）时 reject 抛异常；HTTP 404/500 是"正常响应"——Promise 正常 fulfilled，你要自己检查 res.ok / res.status。全栈代码里忘了这个检查 = 静默的 bug。这是 JS 世界头号新手坑。 
async function getTitle(url: string): Promise<string> {
  const res = await fetch(url);
  if (!res.ok) {
    throw new Error(`HTTP ${res.status}: ${url}`);
  }
  return (await res.json()).title;  // res.json() 也是 Promise！
}

try {
  const title = await getTitle("https://jsonplaceholder.typicode.com/todos/1");
  console.log("todo title:", title);
} catch (err) {
  console.log("请求失败:", err instanceof Error ? err.message : err);
}
错误处理：await 的异常用 try/catch 捕获（和 C# 一样）。注意 instanceof Error 判断——JS 的 throw 可以抛任何东西，字符串也行，所以先判断再取 message。

检查你的理解

Q1 · async 返回类型

  • Promise<number>
  • number
  • void
  • undefined
async 函数永远返回 Promise。函数体里 return 42 只是"把这个值放进 Promise"，调用方必须 await 才能拿到 42。与 C# 的 async Task<int> 相同。

Q2 · await

  • 等待 Promise 完成并取出值
  • 暂停整个程序执行
  • 把异步代码变同步
  • 自动捕获异常
await 挂起当前函数（不是整个程序）直到 Promise 兑现，然后取出值。它不捕获异常（异常要 try/catch），也不"变同步"——事件循环还在跑别的。

Q3 · 并行

  • Task.WhenAll
  • Task.Run
  • Task.Delay
  • async void
Promise.all 并行等待全部完成（任一失败则整体失败）= Task.WhenAll。注意要先把 Promise 创建出来再 all，避免串行。

Q4 · fetch 的错误模型

  • 不抛异常，需检查 res.ok
  • 自动抛出异常
  • 返回 undefined
  • 编译时报错
fetch 只在网络故障时抛异常；HTTP 404/500 是"正常响应"。必须检查 res.ok，否则错误会被静默吞掉。这与 C# HttpClient 默认抛异常的行为相反——最经典的迁移坑。
