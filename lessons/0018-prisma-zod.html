Lesson 0018 · 差异化 · 数据层

数据层：Prisma（类型安全 ORM）+ Zod（校验与类型合一）

数据库和校验你都熟——这课讲 TS 生态的差异化写法：Prisma 的 schema-first（vs EF 的 code-first）、全类型安全的查询链；Zod 的一个 schema 同时产出运行时校验和编译期类型（C# 里三样东西的工作）。

⏱ 15-20 分钟

Prisma：schema-first 的类型安全 ORM

全新概念 Prisma：Node 生态最流行的 ORM。核心差异——schema-first：先写一个独立的 schema.prisma 描述数据模型，Prisma 生成类型安全的查询客户端和数据库迁移。
PrismaEF Core（你的已知）
schema-first：独立 schema.prisma 定义模型code-first：写模型类，EF 推断数据库
生成的客户端：prisma.todo.create(...)db.Todos.Add(...) + DbContext
迁移：prisma migrate devdotnet ef migrations add
查询全程类型安全（条件、字段编译期检查）LINQ 编译期检查（类似）

schema.prisma：模型就是真相

// prisma/schema.prisma —— 唯一的模型定义（vs EF 分散在各实体类）
datasource db {
  provider = "sqlite"   // 开发用 SQLite 零配置；生产换 postgresql 改一行
  url      = "file:./dev.db"
}

model Todo {
  id        Int      @id @default(autoincrement())
  title     String
  done      Boolean  @default(false)
  createdAt DateTime @default(now())
}
$ npx prisma migrate dev --name init
✔ Generated Prisma Client to ./node_modules/@prisma/client（55ms）
Your database is now in sync with your schema.

一次命令做了三件事：① 创建 SQLite 数据库（dev.db）② 建表 ③ 生成类型安全客户端。

类型安全的查询链（差异化核心）

const prisma = new PrismaClient();

// 创建：字段拼错 / 类型不对 → 编译期就报错
const todo = await prisma.todo.create({
  data: { title: "学习 Prisma" },
});

// 查询：条件也是类型安全的（where 的字段名/运算符编译期检查）
const pending = await prisma.todo.findMany({
  where: { done: false },
  orderBy: { createdAt: "desc" },
});
你已经知道 概念上和 LINQ + DbContext 一致：强类型查询、迁移管理。差异：schema 集中定义（vs 分散实体类）、客户端是生成的代码（改了 schema 重新 generate，类型立即同步——类似 EF 的编译时模型但更彻底）。

Zod：一个 schema 搞定校验 + 类型

全新概念 Zod：schema 定义与校验库。差异化在于——一个 schema 同时产出运行时校验和编译期类型： 
import { z } from "zod";

// 定义 schema（这是唯一的真相）
const TodoInput = z.object({
  title: z.string().min(1, "标题不能为空").max(100),
});

// ① 编译期类型：直接从 schema 推导（第 11 课 infer 的实战）
type TodoInput = z.infer<typeof TodoInput>;  // { title: string }

// ② 运行时校验：类型系统管不到网络输入（第 10 课）
const parsed = TodoInput.parse({ title: "" });  // 抛 ZodError: 标题不能为空
C#（你的已知）Zod（新的）
DataAnnotations 校验schema 内联校验规则（min/max/email…）
手写 DTO 类 + System.Text.Json 序列化z.infer 自动推导类型
三样东西（校验属性 + DTO + 映射）一个 schema 全包

组合：Zod 校验边界，Prisma 落库

这是 TS 后端的标准分层（呼应第 10 课"类型管不到网络输入"的解法）：

// API 边界：Zod 校验（拒绝非法输入）→ Prisma 查询（类型安全落库）
async function createTodo(raw: unknown): Promise<Todo> {
  const parsed = TodoInput.parse(raw);        // ① 运行时校验（会抛）
  return prisma.todo.create({ data: parsed }); // ② 类型安全写入
}

检查你的理解

Q1 · schema-first

  • 先定义 schema 再生成模型
  • 先写模型类再生成数据库
  • 不需要数据库
  • 用 XML 文件配置
Prisma 是 schema-first：独立 schema.prisma 定义模型 → 生成类型安全客户端 + 迁移。EF Core 是 code-first：写实体类 → EF 推断数据库。方向相反。

Q2 · infer 实战

  • 从 schema 推导 TS 类型
  • 运行时校验数据
  • 生成数据库表
  • 序列化 JSON
z.infer 用第 11 课的 infer 从 Zod schema 推导出编译期类型——schema 是唯一真相，类型自动跟随（改 schema 类型跟着变）。运行时校验是 parse 的事。

Q3 · 类型安全

  • 字段名和条件编译期检查
  • 运行时自动优化性能
  • 数据库自动建表
  • 不需要定义任何类型
prisma.todo.findMany 的 where/orderBy 字段都是生成的类型——拼错字段名或类型不匹配编译期报错（≈ LINQ 的强类型查询）。

Q4 · parse 时机

  • 运行时校验输入
  • 编译期检查类型
  • 数据库迁移时
  • 打包构建时
parse 是运行时函数：校验实际数据并返回（或抛 ZodError）。它解决"类型系统管不到网络输入"——与 z.infer 的编译期推导互补。
