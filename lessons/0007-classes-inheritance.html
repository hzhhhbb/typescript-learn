Lesson 0007 · 类型系统

类与继承的 TS 细节

类是你最熟悉的领域——所以这课只讲差异。参数属性、两种 private、implements 在结构类型下的意义、abstract、装饰器。你会惊讶有些地方"长歪了"。

⏱ 15-20 分钟

语法对照：基础几乎一样

C# · 你的已知
class Dog : Animal {
  public string Breed { get; }
  public Dog(string name, string breed)
    : base(name) { Breed = breed; }
}
TypeScript · 新的
class Dog extends Animal {
  constructor(name: string, public breed: string) {
    super(name);  // 必须先调 super
  }
}
全新概念 参数属性（parameter property）：constructor 参数带 public/private/protected 修饰符时，TS 自动声明字段并赋值。constructor(public breed: string) 等价于手写 breed: string; 字段 + this.breed = breed;。C# 没有这个糖，是 TS 生态最常见的写法。
你已经知道 继承用 extends（不是冒号），调基类构造用 super()（不是 base()）。单继承、override 语义与 C# 相同。

两种 private：这是最容易踩的坑

TS 里有两种"私有"，语义完全不同：

写法检查时机运行时
private balance编译期软约束（TS2341）编译后是普通属性，运行时可见可改
#secret编译期 + 运行时真私有，外界访问直接抛错
class BankAccount {
  private balance = 0;  // 编译期私有
  #secret = "hidden";  // 运行时真私有

  deposit(amount: number): void { this.balance += amount; }
}

const acc = new BankAccount();
const asAny = acc as any;
console.log(asAny.balance); // 0 —— private 是编译期软约束，as any 能绕开
console.log(acc.#secret);   // ✗ TS18013 + 运行时会抛错
$ npx tsc
src/_err.ts:6:17 - error TS18013: Property '#secret' is not accessible
outside class 'BankAccount' because it has a private identifier.
全栈现实：老代码多用 private（Java/C# 习惯的直接迁移），新代码和库代码越来越多用 #（JS 生态原生的真私有）。混用也常见——封装 API 边界用 #，内部实现细节用 private 即可。

implements：结构类型下的"文档化意图"

第二课讲过：TS 里对象不用显式实现接口，形状匹配即可。那 implements 有什么用？

interface Flyable {
  fly(): void;
}

class Bird implements Flyable {  // 写了 implements：漏掉 fly 会报错
  fly(): void { console.log("flap flap"); }
}
implements 不改变兼容性（结构类型下不写也兼容），它做两件事：① 编译期校验——漏实现成员时在类定义处报错（而不是在赋值处）；② 文档化意图——读代码的人一眼知道这个类承诺实现什么。C# 里 implements 是类型系统必需的；TS 里它是可选的纪律。

abstract 与 getter/setter：和 C# 相同

abstract class Shape {
  abstract area(): number;  // 子类必须实现
  describe(): string {
    return `area = ${this.area().toFixed(2)}`;
  }
}
class Circle extends Shape {
  constructor(private radius: number) { super(); }
  area(): number { return Math.PI * this.radius ** 2; }
}
new Shape();  // ✗ TS2511: Cannot create an instance of an abstract class
class Temperature {
  private _celsius = 0;
  get celsius(): number { return this._celsius; }
  set celsius(v: number) { this._celsius = v; }
  get fahrenheit(): number { return (this._celsius * 9) / 5 + 32; }
}
你已经知道 abstract 类/方法、getter/setter 的语义与 C# 完全相同——直接迁移，不用重新学。小习惯：TS 里私有后备字段常用下划线前缀（_celsius），配合同名 getter/setter。

装饰器预览：@ 语法

Angular、NestJS 等框架大量使用装饰器。TS 5+ 支持标准装饰器（你的 TS 7 环境直接可用，无需 experimentalDecorators 标志）：

function logged(value: any, context: any) {
  console.log(`[decorator] ${String(context.name)}`);
}

class Greeter {
  @logged
  greet(): string { return "hi"; }
}
// 调用 greet() 时输出: [decorator] greet
全新概念 装饰器 ≈ C# Attribute 的"函数版"：Attribute 是声明式元数据（运行时反射读取），装饰器是包裹函数（在声明时执行、可以替换或增强行为）。框架用它实现依赖注入、路由注册、日志等横切逻辑。现在知道存在即可，用框架时再深入。

动手练习

在 code/ 里验证（5 分钟）

我在 code/src/classes.ts 里写好了全部示例（已验证）。做三件事：

  1. 运行 npx tsc && node dist/classes.js，看输出（含装饰器的 [decorator] greet）。
  2. 挑战 1：取消 new Shape(); 的注释，编译看 TS2511，再注释回去。然后取消 console.log(acc.balance); 的注释看 TS2341（private 软约束）——再试试 console.log((acc as any).balance)，会发现绕过了！
  3. 挑战 2：把 private balance 改成 #balance，全部改完后用 (acc as any).balance 访问——发现绕不过去了（真私有）。体会两种 private 的差别。

检查你的理解

Q1 · 参数属性

  • 声明字段并自动赋值
  • 仅声明一个普通参数
  • 声明一个公共方法
  • 声明一个静态字段
参数属性 = 字段声明 + 构造赋值二合一。constructor(public breed: string) 等价于 breed: string; + this.breed = breed;。TS 生态的标准写法。

Q2 · private 的真相

  • 普通属性，运行时可见
  • 运行时强制私有
  • 编译后字段消失
  • 自动变成 # 字段
private 是编译期软约束：类型检查挡住直接访问，但编译后就是普通属性，as any 能绕开。需要运行时真私有用 #字段。

Q3 · # 私有字段

  • 运行时真私有，外部访问抛错
  • 编译期私有，运行时可见
  • 只能用于静态字段
  • 等价于 public 字段
# 是 JS 原生的真私有：编译后保留、运行时强制，as any 也绕不过（TS18013 + 运行时 TypeError）。库代码和封装 API 边界常用它。

Q4 · 继承顺序

  • super()
  • base()
  • this()
  • 不必调用任何东西
TS 用 super()（C# 是 base()）。必须在访问 this 之前调用，否则 TS17009 报错。这是 JS 的类初始化规则。
