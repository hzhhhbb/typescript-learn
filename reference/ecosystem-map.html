TypeScript 生态地图

一图看懂 TS 生态的四层结构。配套课程：0012 npm/npx → 0013 node → 0014 vite → 0015 react。打印出来贴桌边，看项目配置时随手查。

四层全景

你的代码从写到跑，经过四个层。每一层解决一个问题：

框架层：React（0015 课）写界面
用组件声明 UI：<TodoItem title="..." />。TS 类型保护 props 和状态。
npx create-vite@latest · npm run dev
C# 对照：Blazor / Razor 组件（声明式 UI）
↓ 编译 + 打包成浏览器能跑的静态文件
构建层：Vite（0014 课）打包
开发时提供 dev server + 热更新（HMR），发布时把 TS/JSX/CSS 打包成少量静态文件。
npm create vite@latest · npm run dev · npm run build
C# 对照：MSBuild + 发布流程（构建产物）
↓ 运行时执行
运行时层：Node.js（0013 课）跑 JS
执行 JS 的运行时（浏览器之外）。后端代码、构建工具、npm 本身都跑在 Node 上。
node app.js · node --version
C# 对照：.NET 运行时 / CLR（但 Node 只跑 JS，不管类型）
↓ 管理代码包
工具层：npm / npx（0012 课）装包
npm 装依赖（typescript、react、vite 全是 npm 包）；npx 临时运行包里的命令。
npm install · npm run build · npx tsc
C# 对照：NuGet（装包）+ dotnet CLI（跑命令）

一个完整请求的旅程（全栈闭环）

浏览器里 React 组件（框架层）
  → 点击"添加待办"
  → fetch("/todos") 发请求            // 前端 JS
  → Vite 开发服务器把它转给 Node（构建/运行时层）
  → Node 里的 API 处理（Todo API：types/store/server）
  → 返回 JSON
  → React 用数据重新渲染界面

你在第十课写的 Todo API 是"运行时层"的一部分。生态课结束时，你会给它加一个 React 前端——到时候这条链上的每一环你都亲手碰过。

关键心智模型

  • 一切皆包：typescript、react、vite 都是 npm 包。没有"内置框架"——装什么用什么。
  • npm 管装，npx 管跑：装包用 npm，运行包内的命令行工具用 npx（不用全局安装）。
  • Node 是底座：npm、vite、你写的后端全都跑在 Node 上。Node 只认识 JS——TS 必须先编译成 JS（第一课）。
  • 前端要构建：浏览器不能直接跑 TS/JSX，Vite 负责把它们变成浏览器能吃的静态文件。
  • 框架是最后一层：React 解决"界面怎么声明"，底下的工具链它不管。
