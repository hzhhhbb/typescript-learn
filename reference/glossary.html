TypeScript 术语表

所有课程统一使用的术语定义，每条附 C#/Java 映射。打印出来贴在桌边，或随时回来查。

TypeScript (TS)
JavaScript 的超集：在 JS 之上添加了静态类型系统，编译时检查类型，输出纯 JavaScript。
C# 映射：≈ C# 之于 CLR，但 TS 的类型 完全 在编译期擦除，运行时无元数据。
tsc
TypeScript 编译器（TypeScript Compiler）。把 .ts 编译为 .js，同时做类型检查。等价于 javac / dotnet build 的编译角色。
C# 映射：javac / csc —— 但注意 tsc 的产物是 JS 源码，不是字节码。
tsconfig.json
TypeScript 项目的配置文件，声明编译选项（目标版本、严格模式、模块系统等）。等价于 csproj / pom.xml 的配置角色，但极简。
C# 映射：.csproj + Directory.Build.props。
type annotation（类型标注）
显式声明变量/参数/返回值的类型：let x: number。用冒号而不是 Java 的前置式（int x）。
C# 映射：C# 的 int x —— 但 TS 后缀式、且可省略。
type inference（类型推断）
编译器根据初始化表达式自动推导类型，无需显式标注。let x = 42 自动推断为 number。与现代 C# 的 var 相同。
C# 映射：var x = 42;
type erasure（类型擦除）
编译后类型信息全部消失，产物是纯 JavaScript。运行时 没有 类型信息，无法用类型做 instanceof 判断（只能用真实的值判断）。
Java 映射：Java 泛型擦除的极端版 —— TS 连类的类型元数据都不保留。
structural typing（结构类型）
类型兼容性由"形状"（成员结构）决定，而不是由类型名称/声明关系决定。只要一个对象具有所需成员，它就是该类型的合法值。
C#/Java 映射：与名义类型（nominal typing）相反 —— C# 中必须显式实现接口，TS 中只要结构匹配即可。
duck typing（鸭子类型）
"如果它走路像鸭子、叫像鸭子，那它就是鸭子。"JS 的运行时行为：不检查类型，只看对象是否有对应方法。TS 的结构类型是鸭子类型的编译期静态版本——但只检查形状，不检查行为。
C# 无对应（C# 的 dynamic 是最接近的运行时版本）。
excess property check（多余属性检查）
对象字面量直接赋值给某类型时，TS 会检查它有没有多余属性。带多余属性的字面量报错；但先赋给变量再赋值则不报错（因为变量类型在推断后已"定型"）。这是新手最容易踩的坑之一。
C#/Java 无对应 —— 显式实现下不存在"多余属性"问题。
optional property（可选属性）
用 ? 标记可省略的成员：debug?: boolean。该属性存在时类型为 boolean，不存在时视为 undefined。类似 C# 的可空属性，但语义是"可能整个缺席"。
C# 映射：bool? Debug { get; set; }（null 对应缺席）。
nominal typing（名义类型）
C#/Java 的类型兼容模型：两个类型只有存在显式声明的关系（继承/实现）时才兼容。TS 默认不采用此模型。
C#/Java 的默认行为。
union type（联合类型）
一个值可以是几种类型之一：string | number。TS 独有（C# 无直接对应，最接近的是 object 或自定义包装）。
C# 无直接对应。
any
逃逸类型：关闭对该值的类型检查，相当于把 TS 变回 JS。应避免使用（严格模式下通常是隐患信号）。
C# 映射：无 —— 最接近的是 dynamic（且比 dynamic 更宽松）。
unknown
安全的"未知类型"：任何值可赋给它，但使用时必须先收窄（narrowing）到具体类型。比 any 安全得多。
C# 映射：无 —— 最接近的是 object + 模式匹配。
narrowing（类型收窄）
通过运行时检查（typeof、instanceof、in 等）把联合类型收窄为具体类型，编译器据此缩小类型范围。类似 C# 的模式匹配 switch。
C# 映射：is 模式匹配 + switch 表达式。
interface
描述对象形状的类型声明，可被 class 实现或对象字面量直接匹配（结构类型下无需显式 implements）。
C# 映射：interface —— 但 TS 中不需要显式 implements，形状匹配即可。
type alias（类型别名）
用 type X = ... 给类型起名字，可组合联合类型、字面量类型等 interface 表达不了的形状。
C# 映射：最接近的是 using 别名 / 类型包装类。
literal type（字面量类型）
把具体值当作类型：'success' | 'error'。变量只能取这些字面量值。
C# 映射：enum 的弱化版 —— TS 也有 enum，但字面量联合常被更推荐。
void
函数无返回值。与 C#/Java 的 void 相同，但 TS 中更灵活：函数返回 undefined 时也被视为 void 兼容。
C#/Java 的 void，语义略有放宽。
strictNullChecks（严格空检查）
strict 模式的核心开关之一：开启后 null 和 undefined 不能赋给其他类型（必须用联合显式声明）。TS 官方强烈建议开启。
C# 映射：<Nullable>enable</Nullable>（可空引用类型）。TS 更严格——C# 开启后 string? 才可空，TS 中 string 直接不可空。
optional chaining（可选链）
? 操作符：user.address?.city —— 当 address 为 null/undefined 时整个表达式返回 undefined，不抛异常。支持调用、属性、索引、可选链：fn?.()、arr?.[0]。
C# 映射：user?.Address?.City —— 语法完全一样！
nullish coalescing（空值合并）
?? 操作符：a ?? b —— a 为 null/undefined 时返回 b，否则返回 a。注意与 || 的区别：|| 把 0、空串、false 也当"假"，?? 只认 null/undefined。
C# 映射：?? —— 语法和语义完全一样（C# 8+）。
non-null assertion（非空断言）
! 后缀：user.address!.city —— 告诉编译器"这里不会是 null"，跳过空检查。是逃生舱：运行时如果真是 null 会崩。只在确认安全时用。
C# 映射：!（null-forgiving operator）—— 概念完全一样。
strict 模式
tsconfig 中的开关集合，开启全部严格检查（包括 null 检查、noImplicitAny 等）。TS 官方建议始终开启，相当于 C# 的 nullable reference types。
C# 映射：<Nullable>enable</Nullable> 的全面加强版。
module（模块）
TS 的代码组织单位：一个文件一个模块，用 import/export 连接。等价于 C# 的 namespace/程序集组合，但更接近 ES 模块。
C# 映射：namespace + using；Java 映射：package + import。
npm
Node.js 的包管理器，TS 生态的 NuGet/Maven。用 npm install 安装依赖。
C# 映射：NuGet；Java 映射：Maven/Gradle。
generic（泛型）
在声明时用类型参数 <T> 占位，使用时确定：Box<number>。语法与 C# 相似，但运行时完全擦除——编译后 <number> 等参数消失，Box 的实例就是一个普通对象。
C# 映射：List<T> —— 但 C# 泛型保留在运行时（List<int> 与 List<string> 是不同类型），TS 无此区分。
type constraint（类型约束）
用 extends 限制泛型参数必须具有某些成员：<T extends { length: number }>。违反约束时编译报错。
C# 映射：where T : IComparable —— 位置和写法不同，语义类似。
infer
条件类型中的类型提取关键字：T extends (infer U)[] ? U : never —— 从数组类型中"解出"元素类型。C# 完全没有对应物，是 TS 类型编程的标志性工具。
C# 无对应。
type parameter（类型参数）
泛型声明中的 T（也可叫 K、V、U 等）。TS 中默认无约束（可以是任何类型），可用 extends 收紧，也可给默认值：<T = string>。
C# 映射：<T> —— 但 C# 的 T 默认是 object 约束，TS 更宽松。
ts-node / tsx
直接在 Node 中运行 TS 文件的工具（免去先编译的步骤）。等价于"解释执行"，适合脚本和开发环境。
C# 映射：dotnet run / C# Interactive。
function type（函数类型）
函数的类型注解：(a: number, b: number) => number —— 参数列表 + 箭头 + 返回类型。可作为变量类型、参数类型、返回类型。
C# 映射：Func<int, int, int> / 委托类型。
rest parameter（剩余参数）
...args 收集剩余实参为数组：function sum(...nums: number[])。调用 sum(1, 2, 3) 时 nums = [1,2,3]。
C# 映射：params int[] nums。
overload signature（重载签名）
TS 的函数重载：先写多个签名声明（无函数体），最后写一个兼容所有签名的实现。调用时按签名匹配类型。
C# 映射：方法重载 —— C# 写多个同名方法定义，TS 写多个签名 + 一个实现。
optional parameter（可选参数）
用 ? 标记可省略的参数：greeting?: string。调用时不传则为 undefined。也可用默认值：greeting: string = "Hello"。
C# 映射：可选参数（string greeting = "Hello"）。
readonly
标记属性不可重新赋值：readonly id: number。编译期检查（运行时对象仍可变，除非用 Object.freeze）。
C# 映射：readonly 字段（编译期 + 运行时）。TS 只有编译期。
parameter property（参数属性）
constructor 参数带访问修饰符：constructor(public name: string) —— 自动声明字段并赋值，等价于手写 name: string; + this.name = name;。C# 无对应糖。
C# 无对应（需手写字段 + 构造函数赋值）。
#private 字段
JS 原生的真私有字段：#secret。运行时强制（外界访问直接抛错），编译后保留。区别于 private 关键字（编译期软约束，编译后是普通属性）。
C# 映射：private 字段 —— 但 C# 的 private 是运行时真私有，与 TS 的 # 更接近。
abstract
抽象类/方法：abstract class Shape + abstract area(): number。抽象类不能实例化，子类必须实现抽象方法。语义与 C# 相同。
C# 映射：abstract class / abstract method —— 相同。
decorator（装饰器）
@name 语法包裹类/方法/属性，在声明时附加行为。Angular/NestJS 大量使用（@Component、@Injectable）。TS 5+ 支持标准装饰器（需 target ES2022+），早期实验版需 experimentalDecorators。
C# 映射：Attribute —— 但装饰器是函数（可编程），Attribute 是声明式元数据，运行时反射读取。语义不同。
Promise<T>
异步操作的"容器"：表示一个未来才完成（resolve）或失败（reject）的值。Promise<number> = 未来会得到一个 number。状态：pending → fulfilled / rejected。
C# 映射：Task<T> —— 语义非常接近。
async/await
异步语法糖：async function f(): Promise<T> + await promise。await 暂停当前函数直到 Promise 完成并取出值。与 C# 的 async/await 几乎一致。
C# 映射：async Task<T> F() + await task —— 相同。
fetch
发起 HTTP 请求的内置 API：fetch(url) 返回 Promise<Response>。只有网络故障才抛异常——HTTP 404/500 不抛，需要检查 res.ok 或 res.status。这是新手最常踩的坑。
C# 映射：HttpClient.GetAsync —— 但 C# 默认会为 4xx/5xx 抛 HttpRequestException（需 EnsureSuccessStatusCode 语义对比）。
Promise.all
并行等待多个 Promise：await Promise.all([p1, p2]) → 返回结果数组（任一失败则整体失败）。
C# 映射：await Task.WhenAll(...)。
module（模块）
TS/JS 的代码组织单元：一个文件一个模块。有 import/export 语句的文件是模块，有自己的作用域；没有的是"脚本"，声明全局可见。模块之间通过 import/export 连接。
C# 映射：namespace + using 的组合（但粒度是文件级）。
named export / default export（命名导出 / 默认导出）
两种导出方式：export function add() 是命名导出（导入时按名字取）；export default fn 是默认导出（导入时任意起名，一个模块只能有一个）。
C# 无直接对应（C# 没有"默认导出"概念）。
CommonJS (CJS) / ES Modules (ESM)
两种模块格式：CJS 用 require()/module.exports（Node 传统）；ESM 用 import/export（标准）。TS 源码都写 ESM 语法，tsconfig 的 module 字段决定编译产物格式。
C# 映射：.dll 程序集引用（概念对应）。
import type
只导入类型（interface、type 别名等）：import type { User } from "./types"。编译后不产生任何运行时导入语句——因为类型已被擦除。
C# 无直接对应（C# 类型和值导入不区分）。
keyof
提取对象类型的键为联合类型：keyof Todo = "id" | "title" | "done"。是类型编程的基础操作符（类似"属性名集合"，但发生在类型层面）。
C# 映射：反射的 GetProperties() 名字列表（但 C# 是运行时，keyof 是编译期）。
mapped type（映射类型）
遍历键来创建新类型：{ [K in keyof T]?: T[K] }。所有属性变可选/只读等。TS 内置工具类型（Partial、Pick、Record 等）都是它实现的。
C# 无对应（C# 类型不能"遍历生成"）。
conditional type（条件类型）
类型层面的 if/else：T extends U ? X : Y。配合 infer 可提取子类型，是 TS"类型编程"的核心。
C# 无对应。
utility type（工具类型）
TS 内置的类型变换工具：Partial<T>（全可选）、Pick<T, K>（挑键）、Record<K, V>（键值对象）、ReturnType<F>（函数返回类型）等。全栈代码里高频出现。
C# 无直接对应（类型层面没有这类操作）。
